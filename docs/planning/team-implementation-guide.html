1. Product Mission

SmartExpApp helps users reduce waste by making it easy to add products, track expiry dates, get reminders, and turn expiring items into useful recipes.

The app should feel practical, fast, and reliable. The main user should be able to open the app and immediately know which items need attention today, this week, and later.

2. Scope

MVP Features

  1. Persistent inventory with product add, edit, delete, search, filter, and sort.
  2. Expiry dashboard with expired, urgent, soon, and safe groups.
  3. Local reminders before products expire.
  4. OCR-assisted expiry date scanning with user confirmation.
  5. AI Agent screen with voice chat, suggested prompts, and recipe help based on expiring products.
  6. Basic stats for saved, wasted, expired, donated, and consumed items.
  7. Settings for reminders, default storage, and dietary preferences.

Out of Scope for First Release

  • Cloud sync, login, multi-device accounts, and household sharing.
  • Payment, grocery checkout, retailer cart integration, or delivery ordering.
  • Community recipe sharing.
  • Advanced nutrition coaching or medical diet advice.

Delivery Target

The native Android app in app/ is the delivery target. The React/Vite prototype in googleaistudio/ is reference material only unless the team explicitly decides to build a web app later.

5. Storage Strategy

Decision: build local-first storage now, then add cloud sync later.

The first working version should save products, settings, scan history, recipe/Agent context, and inventory actions locally using Room. Cloud storage and Google sign-in should be added after the local product model and repository APIs are stable.

Why Local-First

  • The app remains useful offline and during demos without depending on network or sign-in.
  • Inventory, expiry, notifications, OCR, Agent prompts, and stats all need the same local product data.
  • The team can build faster because UI features do not need to wait for authentication and cloud security rules.
  • Cloud sync can be added behind the repository layer later without rewriting every screen.

Cloud Sync Later

When the local app is stable, add Google Sign-In and a cloud database such as Firebase Firestore. Keep the repository API the same, and add a sync service that mirrors local Room changes to the cloud. 

Phase 1:
UI -> Repository -> Room local database

Phase 2:
UI -> Repository -> Room local database -> Sync service -> Cloud database

Prepare for Future Sync Now

  • Use stable IDs for all local entities.
  • Add createdAt and updatedAt timestamps to syncable records.
  • Keep user-owned data separated from static/reference data.
  • Plan optional future fields: cloudId, ownerUserId, syncStatus, and lastSyncedAt.
  • Recommended sync states: LOCAL_ONLY, PENDING_UPLOAD, SYNCED, and CONFLICT.

6. External APIs

Feature Primary choice How we use it Fallback
OCR expiry date Google ML Kit Text Recognition v2 Extract raw label text, then run our own date parser and ask the user to confirm. Manual expiry date entry.
Product lookup Open Food Facts Product Opener API Fetch product name, brand/category, image, quantity, and nutrition fields when available. Manual product details.
AI Agent Gemini Developer API free tier for text responses; Gemini Live API through Firebase AI Logic for real-time voice if feasible. Answer inventory questions, explain expiring items, generate recipes, and respond to voice or suggested prompts. Android SpeechRecognizer + Gemini text API + Android TextToSpeech for a simpler voice MVP.
Recipe data inside Agent Spoonacular findByIngredients Send expiring item names and rank recipes that use the most urgent ingredients. Edamam Recipe Search API or AI-generated recipe suggestions if Spoonacular is unavailable.

API Key Rule

Do not commit real API keys. Store demo keys in local.properties or an ignored environment file. If this becomes a production app, move recipe API calls behind a backend proxy so the secret key is not shipped inside the APK.

Network Error Rule

Every external API feature must have a useful fallback. The app must still allow manual product entry, manual date entry, suggested prompt use, and no-result Agent/recipe states when the network fails.

AI Privacy Rule

The Agent should only send the minimum inventory context needed to answer the user's question. Avoid sending private notes or unnecessary personal data. Free-tier AI services can have different data-use rules than paid services, so review provider terms before using real personal data.

Rules

  1. Activities and adapters should not directly call Room DAOs or Retrofit services.
  2. Use repository classes as the boundary between UI, database, and network code.
  3. Use one source of truth for product data: the local database.
  4. API responses should be mapped into app models before reaching UI screens.
  5. OCR and Agent results must be treated as suggestions until the user confirms any inventory-changing action.
  6. Keep sample data only as seed/demo data, not as the main runtime data source.

8. Database Contract

Core Entities

Date Rules

  • Store dates as UTC epoch milliseconds or ISO strings consistently. Pick one and use it everywhere.
  • Expiry status should be calculated from the same utility method across all screens.
  • Recommended groups: expired, today, soon, safe.
  • soon means expiring within the user-configured reminder window, default 3 days.

9. Feature Implementation Guide

Inventory

  • Use the database as the source of truth.
  • Support add, edit, delete, search, filter, and sort.
  • Show useful empty states instead of blank screens.
  • Every product card must show name, quantity, storage, expiry status, and category/image if available.

Expiry Dashboard and Reminders

  • Dashboard sections: expired, today, soon, and safe.
  • Use one shared expiry calculation utility.
  • Use notification channels and request notification permission on Android 13+.
  • When a product is updated, consumed, wasted, donated, or deleted, update reminder scheduling.

OCR Expiry Scan

  • Use CameraX or image picker to capture the label.
  • Use ML Kit Text Recognition v2 to extract text.
  • Parse common formats such as EXP 05/28/2026, Best before 28-05-26, and Use by 2026/05/28.
  • Show detected date candidates and require user confirmation.
  • Never silently save an OCR date without user confirmation.

Agent Screen

  • Rename the bottom navigation item from Meals to Agent.
  • The Agent screen should support typed prompts, suggested question chips, and voice input/output.
  • Suggested prompts should include: Give me the recipe for the expiring foods, Recipe for a diet, What should I use today?, and How can I reduce waste this week?.
  • The Agent should read inventory context through repositories, not directly through UI state.
  • Any Agent action that changes inventory must ask for user confirmation first.
  • Recommended MVP: use Android speech-to-text, Gemini text response, and Android text-to-speech.
  • Advanced version: use Gemini Live API for low-latency real-time voice if quota, setup time, and Firebase integration are acceptable.

Recipe Suggestions Inside Agent

  • Start with products expiring soon.
  • Send ingredient names to Spoonacular findByIngredients.
  • Rank recipes by urgency and number of expiring items used.
  • Show used ingredients, missing ingredients, image, title, and source/instructions.
  • Fallback to a no-result state if the API fails.

Stats and Settings

  • Stats should come from InventoryActionEntity, not from hard-coded values.
  • Track consumed, wasted, donated, expired, and saved outcomes.
  • Settings should control reminder timing, default storage, and dietary preferences.

11. Workflow Rules

  1. Use dev as the integration branch.
  2. Keep master stable for final/demo-ready code.
  3. Create work branches from dev.
  4. Use clear, neutral branch names such as 08-stats-settings or 11-ocr-expiry-scan.
  5. Open pull requests into dev, not directly into master.
  6. One pull request should focus on one issue or one tightly related set of changes.
  7. Every pull request should include screenshots or short manual test notes when it changes UI behavior.
  8. Do not commit API keys, generated build folders, or local machine configuration.

Merge Order

  1. Planning and design docs.
  2. Database and repository foundation.
  3. Inventory CRUD.
  4. Expiry dashboard and reminders.
  5. OCR scan.
  6. Agent screen and recipe API.
  7. Stats and settings.
  8. Testing, README, report, slides, and demo.

12. Testing and QA

Required Automated Tests

  • Expiry status calculation: expired, today, soon, safe.
  • Date parser: multiple expiry label formats and invalid text.
  • Repository behavior: insert, update, delete, search, and expiring-soon queries.
  • Agent prompt handling: suggested prompts, inventory context, and fallback states.
  • Recipe mapping inside Agent: used ingredients, missing ingredients, image, and source fields.

Required Manual QA

  • Add product manually.
  • Edit and delete product.
  • Scan expiry date and correct a wrong OCR result.
  • Use the Agent suggested prompts and test API failure state.
  • Use voice input and confirm the app responds with text or spoken output.
  • Receive or trigger expiry reminder notification.
  • Mark items as consumed, wasted, donated, and expired; verify stats update.
